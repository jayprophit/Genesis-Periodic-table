# MAT Change Control

## Purpose

Change control keeps MAT reliable and auditable.

Every significant revision should be visible, reviewable, and traceable to a decision or evidence update.

---

## 1. Change Categories

Examples include:

- schema changes;
- record corrections;
- migration updates;
- evidence reclassification;
- new source ingestion;
- process or method changes;
- supersession or archival actions.

---

## 2. Review Requirement

Not all changes are equal.

A change to a label or documentation note may be minor, while a change to a property value, uncertainty classification, or source status may require stronger review.

---

## 3. Approval Pattern

The project should maintain an explicit process for:

- proposing a change;
- documenting rationale;
- linking evidence;
- recording the reviewer or approver;
- marking the result as accepted, rejected, or deferred.

---

## 4. Documentation Requirement

No change should be hidden in a silent edit.

If a value is updated, revised, or superseded, the record should indicate why.

---

## 5. Scientific Safety

Change control is especially important where a result could affect decision-making, safety, or migration.

This is a core part of MAT's governance discipline.
